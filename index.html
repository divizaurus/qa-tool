Writing better QA comments

      
    
        
  • Be specific about what you tested, not just that you tested it — "verified billing modal upgrade flow from Starter to Pro" beats "tested billing"
    • 
        
  • Always name the branch and environment — a passing test on the wrong branch is not a pass
    • 
        
  • Connected-area notes add real value — mention what you confirmed was not broken, not just what was fixed
    • 
        
  • If you skipped any coverage layer, say so explicitly — "connected-area not checked, deferred" is better than silence
    • 
        
  • Flag observations that aren't blockers — minor UX issues, inconsistencies, or edge cases worth watching
