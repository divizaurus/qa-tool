Writing better QA comments

      
    
        
  • Be specific — "verified billing modal upgrade flow from Starter to Pro" beats "tested billing"
    • 
        
  • Always name the branch and environment — a passing test on the wrong branch is not a pass
    • 
        
  • Mention what you confirmed was not broken, not just what was fixed
    • 
        
  • If you skipped a coverage layer, say so explicitly — silence is not the same as passing
    • 
        
  • Flag observations that aren't blockers — UX oddities, edge cases, things to watch next sprint
